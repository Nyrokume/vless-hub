# Как проходит проверка

Проверка запускается на серверах GitHub Actions за пределами России. Сайт сам никуда не подключает. Адрес, который открылся на раннере, домашний провайдер может закрыть.

Кратко это описано в [README](../README.md). Здесь — полный порядок.

## Очередь

Сначала заново проверяются конфиги, которые уже проходили. Самые давние успешные идут первыми, чтобы короткий прогон успел их обновить. Затем проверяются новые. Потом — те, что в прошлый раз не прошли.

Пинг меньше 15 мс из старых прогонов — это замер открытия порта, не ответ сайта. Такие конфиги проверяются после остальных успешных.

Четыре провала подряд убирают конфиг из очереди. Конфиг, до которого очередь не дошла, не считается нерабочим и серию не портит.

Лимиты полного прогона заданы в `sources.yaml`: до 20 000 проверок порта и до 12 000 проверок через прокси. На один запрос 5 секунд, на весь конфиг 20 секунд.

## Ступени

1. Из текста, HTML и base64-подписки достаются ссылки `vless://`, `ss://`, `trojan://` и `hysteria2://`.
2. Ссылка разбирается. Пустые поля и разный регистр имён параметров не ломают разбор. Обрезанная ссылка, неверный идентификатор VLESS, Reality без ключа и имени сервера, порт вне 1–65535 дальше не идут.
3. Одинаковые серверы с разным названием, отпечатком TLS или порядком параметров схлопываются в один.
4. Проверяется, открыт ли TCP-порт. Для Hysteria2 этот шаг пропускается: протокол работает по UDP.
5. Через уже запущенный Xray (или sing-box для Hysteria2) проходит подключение. Один прогревочный запрос в пинг не входит.
6. Три адреса должны ответить кодом 200 или 204. Нужно большинство ответов. Пинг — медиана времени до первого байта успешных ответов.
7. Скачивается короткий файл около 250 КБ. Если данные почти не идут, конфиг не проходит.
8. Сверяется адрес выхода. Если он совпал с адресом раннера, трафик прошёл мимо прокси.

## Статусы

Окно истории — 10 последних проверок. Оно хранится в `data/stability.json` на Pages и в git не коммитится.

| Статус | Что значит | Куда попадает |
| --- | --- | --- |
| Рабочий | Прошёл сейчас и держится хотя бы в 70% последних проверок | Основной список и `sub/all.txt` |
| Нестабильный | Прошёл сейчас, но реже 70% | `sub/with-unstable.txt` и отдельная кнопка на сайте |
| Не работает | Сейчас не прошёл | В списки не входит |

Удачный проход остаётся в списке, пока повторная проверка его не завалит или с момента прохода не пройдёт 6 часов. Так список не схлопывается, если короткий прогон не успел перепроверить всех.

На строке залитая точка — рабочий, пустая — нестабильный. «Только открытый порт» значит, что сервер ответил, а полный проход в этот раз не делали. Такие строки лежат в `sub/unverified.txt`.

## Цвета и числа

| Что видно | Значение |
| --- | --- |
| Зелёный пинг | Быстрее 300 мс |
| Жёлтый пинг | От 300 до 800 мс |
| Красный пинг | Медленнее 800 мс |
| Процент | Доля успешных проверок в окне |
| Скорость | Как быстро скачался короткий файл, в КБ/с или МБ/с |

Страна берётся по адресу выхода. Флаг из названия ссылки остаётся только если адрес выхода не определился.

## Причины отказа

В статистике пишется ступень, на которой конфиг остановился. На сайте эти коды показаны обычными словами.

| Код | На сайте | Когда |
| --- | --- | --- |
| `parse_error` | Ссылка не разобралась | Текст не удалось прочитать как ссылку |
| `invalid_field` | Ошибка в поле | Поле есть, но значение неверное |
| `tcp_refused` | Сервер отклонил подключение | Порт закрыт или сразу отказал |
| `timeout` | Нет ответа | Тишина на порту, при подключении или при запросе |
| `tls_fail` | Ошибка TLS | Защищённое подключение не установилось |
| `reality_fail` | Ошибка Reality | Не прошёл Reality |
| `handshake_fail` | Не удалось подключиться | Рукопожатие оборвалось по другой причине |
| `http_fail` | Сайт не открылся | Ответы не набрали большинство 200/204 |
| `no_data` | Подключается, но не передаёт данные | Сокет жив, полезных байт мало |
| `exit_ip_leak` | Трафик идёт мимо прокси | Адрес выхода совпал с раннером |
| `dead` | Не работает | Конфиг не прошёл текущую проверку |

## Прокси Telegram

MTProto, включая секрет с префиксом `ee`, должен дойти до ответа сервера Telegram, который возвращает отправленный код. SOCKS делает подключение к `149.154.167.51:443` и тот же обмен.

Отказ сокета — «Сервер отклонил подключение». Тишина — «Нет ответа». Битый ответ — «Не удалось подключиться». Статусы те же: рабочий, нестабильный, не работает. За один прогон проверяется до 160 прокси.

## Пределы

- Проверка не из России и не из сети пользователя.
- Пинг измеряется после подключения, без времени установки туннеля.
- Очередь конечная. Непроверенные в этом прогоне не помечаются мёртвыми.
- Источник, у которого два прогона подряд почти нет рабочих ссылок, отодвигается в конец очереди.
- «Живой парс» в браузере только читает открытые списки. Он не проверяет новые строки. «Запустить проверку» открывает страницу GitHub, где владелец запускает настоящий прогон.
