# vless-hub

Автоматический сборщик и тестер публичных VLESS-конфигов с сайтом на GitHub Pages.

Сайт не поднимает VPN-туннель. Он показывает результат сборщика и помогает скопировать ссылку, открыть QR или передать подписку в клиент (`v2raytun://import/`, `happ://`, `v2rayng://`, `hiddify://`).

## Сборщик

`collector/collect.py` (стандартная библиотека плюс бинарник Xray):

1. Скачивает публичные списки из `collector/sources.json`: VLESS, Telegram MTProto, SOCKS5 и HTTP.
2. Разбирает ссылки и убирает дубликаты. TCP-подключение только отсекает мёртвые адреса и не попадает в опубликованную задержку.
3. Для VLESS поднимает Xray с локальным SOCKS и конфигом как outbound, затем меряет HTTP 204 (`generate_204`, запасной адрес Cloudflare). В список попадают только ответы 204. Медиана 2–3 попыток, таймаут около 5 с.
4. SOCKS5 и HTTP проверяет тем же HTTP 204 через прокси (`check: "real"`). MTProto — рукопожатие obfuscated2 или fake-TLS; если ответа нет, остаётся честная пометка `check: "tcp"`.
5. Определяет страну по флагу в названии или через GeoIP и пишет данные для сайта.

Пути результата (их используют сайт и Pages):

| Файл | Содержимое |
| --- | --- |
| `data/configs.json` | Метаданные, статистика, лучший конфиг, подписки, конфиги и прокси |
| `data/best.txt` | Один `vless://` с наименьшим real-delay |
| `data/subs/<id>.txt` | Текстовая подписка |
| `data/subs/<id>.b64.txt` | Та же подписка в base64 |

Группы конфигов: все рабочие, быстрые (real-delay ≤ 800 мс), Reality, TLS и транспорты, для которых нашлись конфиги. Прокси: `subs/mtproto.txt`, `subs/socks5.txt`, `subs/http.txt`.

```bash
python3 collector/collect.py
python3 -m unittest discover -s . -p 'test_*.py'   # из каталога collector
```

Xray ищется в `--xray`, затем в `XRAY_BIN`, `collector/bin/xray` и `PATH`. Workflow качает официальный релиз и сверяет SHA256. Если все источники недоступны, скрипт завершается с ошибкой и не затирает уже лежащие файлы. Если недоступны только VLESS или только прокси, сохраняется предыдущая половина.

## Сайт

Интерфейс на React, Vite, Tailwind и shadcn/ui (нейтральная тема, тёмная по умолчанию).

- Подключение: карточка лучшего сервера открывает его и основную подписку в v2RayTun (`v2raytun://import/` + сырой `vless://` или URL подписки, без base64). Рядом Happ, v2rayNG, Hiddify и копирование.
- Статистика real-delay: рабочие конфиги, прокси, страны, медиана.
- Плитки «Конфиги» и «Прокси»: все рабочие, быстрые, Telegram MTProto, SOCKS5. У каждой есть список и открытие в клиенте; MTProto открывается как `tg://proxy`.
- Переключатель списка Конфиги/Прокси, поиск, фильтры, сортировка, QR и подробности. У прокси с проверкой TCP задержка подписана «мс TCP».
- Настройки в `localStorage`: тема, сортировка, порог, клиент, адрес сайта.
- Блок «Информация»: версия, сборщик, время последнего запуска, статистика, источники.

Базовый путь сборки — `/vless-hub/`. Данные запрашиваются с `data/configs.json` относительно этого пути.

```bash
cd site
npm ci
npm run dev      # http://localhost:5173/vless-hub/
npm run build
npm run preview
```

## GitHub Actions

- `.github/workflows/collect.yml` — по расписанию и вручную обновляет `data/` и коммитит изменения. Пуш в `main` запускает публикацию сайта.
- `.github/workflows/pages.yml` — собирает `site/` и вместе с `data/` выкладывает GitHub Pages. В настройках репозитория источник Pages должен быть «GitHub Actions».

Канонические ссылки подписки после публикации:

- https://nyrokume.github.io/vless-hub/data/subs/all.txt
- https://nyrokume.github.io/vless-hub/data/subs/all.b64.txt

Адрес можно сменить в настройках сайта, если репозиторий форкнут.
