# V2Hub

Публичный агрегатор VLESS, Shadowsocks, Trojan, Hysteria2 и прокси Telegram. Сайт на React и shadcn/ui, сборщик на Python: VLESS, Shadowsocks и Trojan проходят HTTP через Xray, Hysteria2 — через sing-box, MTProto и SOCKS проверяются рукопожатием до датацентра Telegram.

Страница: https://nyrokume.github.io/vless-hub/

Сборщик только читает уже опубликованные ссылки, измеряет их с раннера и выкладывает списки. Он не поднимает туннель в браузере и не обещает, что адрес останется рабочим.

## Что публикуется

В подписку по умолчанию попадают только конфиги со статусом «рабочий»: они прошли текущий прогон и держатся хотя бы в 70% последних десяти. «Нестабильный» прошёл сейчас, но реже — он есть в `sub/with-unstable.txt` и на сайте по отдельной кнопке. «Мёртвый» в списки не входит. Открытый TCP-порт без полного прохода лежит в `sub/unverified.txt`. Hysteria2 — UDP, поэтому TCP-предфильтр для него не используется. Пинг — медиана нескольких HTTP-запросов через уже запущенное ядро, без прогрева. Страна берётся по IP выхода; флаг из замечания остаётся только если адрес выхода не определился. Имя в подписке собирается заново: флаг, эта страна, протокол, транспорт и измеренные миллисекунды.

## Как разбирается и проверяется ссылка

1. Из текста, HTML и base64-подписки достаются `vless://`, `ss://`, `trojan://` и `hysteria2://`.
2. Shadowsocks читается как SIP002: userinfo в base64 бывает с `=`, без padding и с `%3D%3D`. Старая форма `ss://base64(method:password@host:port)` тоже принимается. У VLESS `type=http` вместе с `mode` (`packet-up`, `stream-one`, `stream-up`, `auto`) или `extra` — это XHTTP, JSON из `extra` уходит в Xray. `type=raw` — это TCP. Пустые `fp=` и `headerType=` не ломают разбор. `headerType=http` сохраняет список хостов. Регистр `allowInsecure` / `headertype` не важен, лишний `&` в начале query пропускается.
3. Мусор вычищается. В `alpn` остаются только `h3`, `h2`, `http/1.1`, `http/1.0`. В `host` — только правдоподобные имена и IP. Параметры вроде `Telegram=@…` отбрасываются. Обрезанная ссылка, не-UUID у VLESS, Reality без нормального `pbk` и имени `sni`, порт вне 1–65535 не проходят дальше.
4. Одинаковые серверы с разным `fp`, замечанием или порядком параметров схлопываются. Из вариантов отпечатка остаётся `chrome`.
5. Проверка идёт ступенями, и в статистику пишется ступень, на которой конфиг умер:
   - `parse_error` / `invalid_field` — ссылка не разобралась или поле неверное;
   - TCP до `server:port`: нет ответа вовремя — `timeout`, отказ сокета — `tcp_refused`;
   - рукопожатие через уже запущенный Xray (TLS, Reality, WS, gRPC, XHTTP) или sing-box для Hysteria2: `tls_fail`, `reality_fail`, `handshake_fail` или `timeout`. Это один прогревочный запрос, его время в пинг не входит;
   - три независимых HTTP-адреса (`gstatic`, `cp.cloudflare.com`, `google` `generate_204`), у каждого один повтор. Нужно большинство ответов 200/204. Иначе `http_fail` или `timeout`. Пинг — медиана времени до первого байта успешных заходов;
   - загрузка около 250 КБ с `speed.cloudflare.com`. Сокет без данных — `no_data`, в строке остаётся КБ/с;
   - адрес выхода (`api.ipify.org`). Если он совпал с адресом раннера, прокси не использовался: `exit_ip_leak`. Страна этого адреса идёт в группировку.
   На один запрос 5 с, на весь конфиг 20 с. Конфиг, до которого очередь не дошла, не считается мёртвым и не портит серию.
6. Серия успехов хранится в `data/stability.json` на Pages (ключ — нормализованный отпечаток, окно 10 прогонов) и не коммитится в git. «Рабочий» — прошёл сейчас и доля ≥ 70%. «Нестабильный» — прошёл сейчас, но доля ниже. «Мёртвый» — не прошёл сейчас. Четыре провала подряд убирают конфиг из пула совсем.
7. У каждого источника считается доля прошедших проверку. Два прогона подряд почти без рабочих ссылок отодвигают его в конец очереди.

Прокси Telegram получают те же статусы. MTProto (в том числе ee с fake-TLS) должен дойти до `resPQ`, который возвращает наш nonce. SOCKS5 делает CONNECT на `149.154.167.51:443` и тот же обмен. Отказ сокета — `tcp_refused`, тишина — `timeout`, битый ответ — `handshake_fail`.

Проверка запускается на серверах GitHub Actions вне России. Конфиг, который открылся там, домашний провайдер всё равно может закрыть.

Срезы `reality`, `tls` и транспортов — только VLESS, чтобы Shadowsocks не попадал в `tcp`. `data/configs.json` кормит сайт. Эти файлы не коммитятся. В git лежит компактное состояние `state/history.json`, `state/tg_history.json`, `state/geo_cache.json`, `state/source_health.json`. Серия для статусов — `data/stability.json` в артефакте Pages, её workflow в git не добавляет.

## Сайт

Тёмная тема — чёрный фон и белый текст, светлая — белый фон и чёрный текст. Первый заход смотрит `prefers-color-scheme`, переключатель запоминает выбор. Вкладки: «Конфиги», «Telegram Proxy», «Экспорт», «Инструкции». В шапке — время последнего обновления текстом. Список по умолчанию сгруппирован по странам: флаг, название, число и лучший пинг, внутри группы пинг по возрастанию. Порядок стран переключается между числом и лучшим пингом, рядом есть плоский список с общей сортировкой. Длинный список рисуется окном, QR собирается только по нажатию. Строка показывает точку (рабочий или нестабильный), долю успешных прогонов, пинг и скорость. На «Инструкциях» блок «Проверка» считает причины отказа. «Экспорт» отдаёт файлы по срезу, конструктор подписки и схемы клиентов. На «Конфигах» можно отметить строки и выгрузить текст, base64, файл, QR, Clash или sing-box. QR чёрный на белом, со скачиванием PNG. Схемы только проверенные: Happ, v2rayNG, Hiddify, v2RayTun, NekoBox, Clash Meta, Mihomo, sing-box. «В Telegram» открывает `tg://`. «Инструкции» разбирают `vless://` локально.

## Запуск

```bash
pip install -r requirements.txt
python -m pytest
python -m vlesshub run --out publish --site site
cd site && npm ci && npm run build
```

Полный прогон качает Xray, sing-box и GeoIP. Пул — до 20000 TCP (200 потоков, таймаут 2,5 с) и до 12000 прокси. Прокси идут пулом: 12 процессов Xray, в каждом до 24 SOCKS, то есть около 288 конфигов сразу; Hysteria2 — sing-box, пачка не больше 8. На запрос 5 с, на конфиг 20 с. Худшая волна из 12000 конфигов — примерно 42 волны по 32 с, около 25 минут, плюс TCP. Это укладывается в лимит job 55 минут; отдельная матрица job не используется, потому что серия и история общие. Telegram — до 160 рукопожатий, 40 потоков. Очередь: сначала ещё не проверенные, затем давно не перепроверенные рабочие, потом повтор неудачных. Четыре провала подряд в пул больше не попадают. В `all.txt` только «рабочие» этого прогона, по пингу, без обрезки; прошлый успех без свежей проверки в список не переносится. Для короткой проверки: `--max-tcp 20 --max-proxy 0 --max-tg 0`. Код выхода 2 значит, что в этом прогоне никто не прошёл прокси, а история уже знает рабочие: состояние сохраняется, сайт не затирается.

Расписание — `.github/workflows/update.yml`, cron `17 */6 * * *` и ручной запуск. Один workflow гоняет тесты, сборщик, сборку React и деплой на Pages.
